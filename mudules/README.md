# mudules/ — 技术最佳实践库

本目录存放**技术栈级**的最佳实践 skill（与项目业务无关）。`feature-tech-design` 做技术方案时**强制检索**本目录：命中即按其最佳实践设计并标注依据；未命中则检索该技术官方文档并留痕（优先级：`specs/` 项目红线 > `mudules/*-usage` > 官方文档）。

## 目录约定（每个技术一个 `<tech>-usage/`）

```text
mudules/
├── README.md                  # 本文件：目录约定与检索协议
├── abp-usage/
│   ├── SKILL.md               # 心法、分层决策表、铁律、常见坑、检索方法
│   └── references/
│       ├── 00-directory-tree.md   # ★ 技术目录树（必含，见下）
│       ├── 01-ddd-layering.md     # 分层教程
│       └── …
└── mysql-usage/
    ├── SKILL.md
    └── references/
        ├── directory-tree.md      # ★ 技术目录树（必含）
        └── …
```

## 强制要求：技术目录树

每个 `*-usage` skill **必须**包含一份「技术目录树」（`references/` 下 `*directory-tree*.md`），内容为该技术的标准工程/资产组织结构：

1. **完整目录树**（代码块 + 注释）：该技术的标准项目结构——分层、每层放什么；
2. **"放哪里"决策表**：常见产物（实体/服务/配置/脚本/迁移/文档）逐项给出归属目录；
3. **反模式**：禁止放置的位置（如业务逻辑放进表现层、SQL 散落在代码目录）；
4. **来源**：提炼自该技术官方文档/官方模板，标注出处。

技术目录树是"技术方案 → 目录落地"的桥梁：feature-tech-design 画完架构图后，依据它把新模块落到正确目录；发现项目实际结构与目录树不符时，先核对项目 `specs/项目目录结构.md`（项目定制优先），偏离需在方案中说明理由。

## 新增技术 checklist

- [ ] 目录命名 `<tech>-usage/`
- [ ] SKILL.md：description 含触发意图；正文含心智模型、铁律、检索方法
- [ ] references/ 含**技术目录树**（必含）+ 其余按需
- [ ] 内容提炼自官方文档，标注来源，不含项目业务规则
